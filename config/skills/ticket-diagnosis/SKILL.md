# 工单诊断

## 目标

把用户问题与指定 ERP 工单转换为可核实的诊断结论。当前系统只提供分析辅助，不回写 ERP/MES，也不执行数据库写操作。

## 执行流程

1. 必须先调用 `read_external_case` 读取指定工单，不能仅凭用户转述开始判断。
2. 从工具结果提取错误信息、模块、业务对象、工件号、时间、环境和附件线索，区分已确认事实与推测。
3. 证据足够时给出故障方向、影响与建议；证据不足时输出 `inconclusive`，并说明还缺什么。
4. 只有出现明确的错误、模块、类名、函数名或版本变更线索，且代码证据能推进判断时，才调用 `skill` 加载 `code-investigation`。
5. 加载代码调查 Skill 后不要退出或另起 Agent；在当前循环继续调用可用的 GitHub 只读 Tool，并把代码证据与工单事实合并。
6. 如果当前没有 GitHub Tool，保留已经取得的工单证据，并明确说明“GitHub MCP 工具暂时不可用”。

## 深入规则

需要判断证据强弱、冲突或停止条件时，调用 `read_skill_reference` 读取 `references/evidence-rules.md`。不要在不需要时加载参考资料。

## 输出要求

- 明确标注事实、推断和待验证项。
- 引用工单号及相关字段，不伪造数据库、代码、附件或日志证据。
- 结论必须可供业务人员理解，技术细节放在证据说明中。
