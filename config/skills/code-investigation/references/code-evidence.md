# 代码证据规则

## 最小引用

代码证据至少包含：仓库标识、Commit SHA、文件路径、相关符号或片段摘要。只有文件路径而没有固定 Commit 时，必须标注“版本未固定”。

## 调查顺序

1. 搜索稳定锚点定位候选代码；
2. 读取最少必要文件确认上下文；
3. 需要解释变化时查询提交历史；
4. 将代码事实与工单、SQL 或日志证据交叉验证。

## 结论边界

- 代码存在某分支或字段映射，只能证明实现事实。
- 某提交修改相关逻辑，只能证明变更事实。
- 只有代码事实与运行证据共同指向同一机制时，才能提高根因置信度。
- 无运行日志、SQL 结果或复现结果时，不得把候选代码直接写成确定根因。
